# 0001 — Topic retrieval: exact match now, evaluate semantic fallback later

**Status:** Accepted
**Date:** 2026-09-24
**Context:** build-plan T036 (`RealOpenVikingClient.get_relevant_knowledge`)

## Decision

`get_relevant_knowledge(topic)` looks up existing knowledge by an **exact** match on the topic string (a glob within that topic's own directory under `viking://resources/knowledge/`), not OpenViking's semantic `search/find`.

## Why

The topic string isn't user-defined or predefined anywhere — it's generated by the LLM during the Extract step, once per candidate, per meeting. The Compare step immediately looks up that exact same string to check for existing knowledge before classifying new/corroborating/superseding/contradicting. Within one pipeline run, exact matching is precise, fully deterministic, fast, and easy to test — no dependency on embedding model behavior.

## The known gap

If the LLM extracts different topic wording across two separate meetings about the same underlying subject (e.g. "enterprise_sso" vs. "single_sign_on"), exact matching won't connect them. The Compare step will call it "new" both times instead of noticing they're related — so the system can end up with several disconnected topic threads about what a person would recognize as one subject.

## Alternatives considered

- **Exact match with a semantic fallback** when no exact hit exists. Rejected for now: since most topics genuinely are new on first mention, this would add a semantic search call (and its latency, on an already-slow local model) to the common case, not just the rare one it's meant to help. It also risks false-positive matches on merely-related-sounding topics, which would show up as spurious contradictions routed to human review (PRD §17) — real toil, not just noise.
- **Canonicalizing topic strings** (e.g. constraining the LLM to a fixed/managed topic vocabulary). Rejected for now as more moving parts than the MVP needs.

## Revisit when

Real meeting data through the pipeline shows whether topic-name drift across meetings is an actual, frequent problem or a theoretical one. If it's real, the semantic-fallback approach above is the first thing to try.
